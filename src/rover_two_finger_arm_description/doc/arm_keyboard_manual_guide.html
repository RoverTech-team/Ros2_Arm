🦾 Rover Arm — Manual Keyboard Control

This guide explains how to launch the arm alone (no rover base, no Gazebo, no MoveIt) on mock hardware and jog every joint by hand from the keyboard. The stack that gets started:

  • ros2_control_node with the mock_components/GenericSystem hardware plugin (from urdf/arm.urdf.xacro)
  • joint_state_broadcaster → publishes /joint_states
  • arm_controller (JointTrajectoryController: j1, j2, j3, wrist pitch, wrist roll)
  • gripper_controller (JointTrajectoryController: slider → 3-finger gripper)
  • robot_state_publisher + RViz (optional) so you can watch the arm move
  • Keyboard teleop node in its own xterm window
  • Gamepad teleop node subscribing to /joy (PS4/Xbox controller — see below)

🚀 Quick start

# 1. Source the RoboStack ROS 2 Humble environment (outside the repo)
source ~/Documents/Polispace/ros2_humble/local_setup.zsh
export ROS_LOCALHOST_ONLY=1        # required on macOS for DDS discovery

# 2. Build the package (needed once — new files were added)
cd ~/Documents/Polispace/LOCAL/ROS_Control/Ros_control
colcon build --symlink-install --packages-select rover_arm_description
source install/setup.zsh

# 3. Launch arm + controllers + keyboard teleop + RViz
ros2 launch rover_arm_description arm_keyboard_manual.launch.py

A new xterm window opens automatically with the teleop status line — that window must stay focused to capture your key presses. RViz shows the arm moving in real time. Close everything with Ctrl+C in the launch terminal.

The teleop status line shows the live step size and every joint position (angles in degrees, gripper travel in mm), e.g. 

status: step 2.9 deg (5.0 mm) | j1   +12.3  j2   -45.0  j3   +30.0  pitch  +90.0  roll    +0.0  grip  25.0 mm
Tip: keys are read one press at a time — holding a key down repeats thanks to the keyboard auto-repeat. Watch the status line: when a joint limit is hit the teleop prints [joint] joint limit reached and refuses to move further.

🎮 Gamepad control (PS4 / Xbox)

The launch also starts a gamepad teleop that subscribes to the standard sensor_msgs/Joy topic and jogs every joint continuously — analogue sticks act like velocity knobs, unlike the fixed keyboard steps. 

ros2 launch rover_arm_description arm_keyboard_manual.launch.py

joy_source picks who publishes /joy:

ValueSourceWhere
auto (default) standard joy_node on Linux, pygame publisher otherwise picks the right one per OS
ros ros2 run joy joy_node reading /dev/input/js0 production: Jetson Orin NX, Ubuntu 22.04 + ROS 2 Humble (sudo apt install ros-humble-joy, and add yourself to the input group: sudo usermod -aG input $USER, then re-login)
pygame bundled arm_joy_publisher.py (DS4 over Bluetooth works out of the box) dev: macOS (pygame is installed in the RoboStack env)

Safety behaviour

  • Deadman: sticks do nothing unless L2/R2 is held (≥ 50 %).
  • Stale-data watchdog: if /joy stops arriving (gamepad battery dies, Bluetooth drops, publisher crashes), the deadman auto-releases after 0.5 s and the arm freezes — it never keeps moving on the last cached message.
  • E-stop: triangle latches motion off; press again to re-enable.
  • URDF limits: same clamping as the keyboard teleop; a stick pushed against a joint limit simply stops contributing.

Speeds are parameters of the teleop node: max_speed (rad/s, default 0.8), wrist_speed (default 1.0), slider_speed (m/s, default 0.02), deadzone (default 0.08). Axis/button layouts follow two profiles — sdl (macOS/pygame, triggers on axes 2/5) and joydev (Linux joy_node, right stick on axes 2/3, triggers on 4/5) — selected automatically by joy_source, override with -p profile:=joydev if your pad maps differently.

Tip (Jetson): verify the pad first with ros2 topic echo /joy while pressing buttons — if nothing publishes, the pad is on js1 (set device_id) or the input group membership hasn’t taken effect yet.

🖥 Running the teleop manually

ros2 launch does not forward keyboard input to its processes, which is why the teleop opens in its own xterm. If XQuartz/xterm is not installed (the launch prints a reminder) or you prefer your own terminal, start the teleop by hand in a second terminal: 

# Terminal 1 — everything except the teleop window
ros2 launch rover_arm_description arm_keyboard_manual.launch.py teleop:=false

# Terminal 2 — keyboard teleop
source install/setup.zsh
export ROS_LOCALHOST_ONLY=1
ros2 run rover_arm_description arm_keyboard_teleop.py

The node accepts the same knobs as parameters:

ros2 run rover_arm_description arm_keyboard_teleop.py --ros-args -p step:=0.1 -p duration:=0.5

🩺 Troubleshooting

SymptomFix
Nothing discovers anything; spawners hang Export ROS_LOCALHOST_ONLY=1 in every terminal (macOS DDS multicast issue — see README).
No xterm window appears Install XQuartz (xterm lives in /opt/X11/bin) and restart the terminal, or run the teleop manually as shown above.
Teleop prints “stdin closed” It was started without a keyboard attached — run it via ros2 run in a real terminal.
Keys move nothing; list_controllers shows inactive Wait a few seconds after launching; the controllers are spawned after joint_state_broadcaster. Re-run the launch if a spawner errored.
Gamepad connected but nothing moves Hold L2/R2 (deadman) while pushing the sticks; check the pad publishes with ros2 topic echo /joy; on Jetson make sure ros-humble-joy is installed and you are in the input group.
Arm keeps drifting after releasing the sticks It shouldn’t — the deadman and the 0.5 s /joy watchdog stop all motion. If it does, check that only one teleop node is running (ros2 node list).
Sticks move the wrong joints / triggers don’t gate motion Your pad’s axis layout doesn’t match the auto-selected profile — switch with ros2 run rover_arm_description arm_joy_teleop.py --ros-args -p profile:=joydev (or sdl).
Arm shows as boxes/ghost in RViz Known macOS limitation: RViz can’t render the .dae meshes with the default renderer — geometry still moves correctly (see README “Known Issues”).
Gripper fingers don’t close in RViz The fingers are URDF mimic joints; the mock hardware plugin doesn’t animate them — the slider itself moves. In Gazebo the fingers follow the slider.
